# TinyLap Identity and Workspaces Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One optional TinyLap login for the whole suite. It has three parts: `apps/accounts`, a passkey-only OIDC provider on Better Auth with workspaces and roles; `packages/auth`, standard OIDC helpers; and the planner as the first client, with a private library.

**Architecture:** `apps/accounts` is a Node 24 `node:http` server that mounts Better Auth (`toNodeHandler`) at the root. It stores everything in `node:sqlite`: Better Auth's tables plus TinyLap's own (`workspace`, `membership`, `invite`, `recovery_code`, `deletion`). Its pages are server-rendered with palace-ui, and the browser-side WebAuthn calls use only the platform API. `packages/auth` wraps `openid-client` and `jose` for app servers acting as a backend-for-frontend. The planner gets `/auth/*`, a session table, private snapshots and a library API, and checks access tokens and roles with `packages/auth`.

**Tech Stack:**
- Node 24, plain ES modules with JSDoc, `node:test`
- `better-auth`, `@better-auth/oauth-provider` and `@better-auth/passkey`, all at exactly 1.7.7, used only inside `apps/accounts`
- `openid-client` 6 and `jose` 6, in `packages/auth`
- Playwright with Chrome's virtual WebAuthn authenticator, for browser tests
- Fly.io

**Spec:** `docs/superpowers/specs/2026-10-14-identity-design.md`. Read it in full before each task; section numbers below refer to it.

## Global Constraints

- **Better Auth stays inside `apps/accounts`.** Nothing else imports `better-auth` or `@better-auth/*`. Other code talks to `accounts` through standard OIDC/OAuth endpoints only.
- **Exact pins:** `better-auth`, `@better-auth/oauth-provider` and `@better-auth/passkey` at `1.7.7` exactly (no `^`); `openid-client` `^6.8.8`; `jose` `^6`.
- **Algorithms and lifetimes:**
  - ID tokens and access tokens are signed with RS256. `verifyAccessToken` accepts only RS256.
  - Access tokens live 10 minutes. Refresh tokens live 30 days and rotate on use. The `accounts` browser session lasts 30 days.
  - The planner session cookie is `__Host-tinylap-session` (`HttpOnly; Secure; SameSite=Lax; Path=/`), 30 days sliding, capped at 90 days after login.
- **Access tokens carry `workspaces: [{ id, role }]`.** Roles are `owner` | `admin` | `member`. Permissions follow the §5 matrix exactly.
- **Passkeys only:** `residentKey: required`, `userVerification: required`, `attestation: none`, challenges single-use and 5 minutes. No passwords, no email sending. Better Auth's email field holds `<id>@users.invalid`.
- **Recovery codes** are `<lookup_id>.<secret>`, with a secret of at least 80 bits. The hash is SHA-256, compared in constant time and spent atomically. There are ten per set.
- **Quotas (§4):**
  - 200 tracks per workspace;
  - the 50 newest versions per track are kept;
  - 64 KiB canonical size per snapshot;
  - 60 saves per user per hour;
  - 5 clubs created per user;
  - 20 active invites per workspace.
- **Rate limits per client, IPv6 per /64:** sign-up 10/h, sign-in 30/h, recovery 10/h per client and 5/h per `lookup_id`, invite redemption 20/h.
- **Local dev and tests run over `http://localhost`.** `accounts` accepts loopback redirect URIs only with `TINYLAP_DEV=1`, and refuses to start with `TINYLAP_DEV=1` when its issuer is https.
- **Errors** are RFC 9457 Problem Details. New types: `quota-exceeded` (422), `forbidden` (403), `unauthorized` (401).
- **Library and auth routes never send `Access-Control-Allow-Origin: *`.** Private responses are `Cache-Control: private, no-store`. Strangers get 404, never 403.
- **Every UI follows `AGENTS.md`:** palace-ui plus `@tinylap/design`. Any subagent touching UI must use the `frontend-design` skill.
- **Repo conventions:**
  - SPDX headers: `apps/**` and `tools/**` AGPL-3.0-or-later, `packages/**` MPL-2.0, `docs/**` CC-BY-SA-4.0.
  - Conventional commits with `git commit -s`, author `1009814+jostsg@users.noreply.github.com`, **no AI attribution of any kind**.
  - `pnpm check` green before every commit.
  - Test output must be pristine. Planner and accounts tests run with `--disable-warning=ExperimentalWarning`.

## Review Focus

1. **A user removed from a club must lose access within one token lifetime,** and their refresh tokens must stop working. Task 4 pins this.
2. **Two planner requests refreshing the same session at the same time must not log the user out.** Task 6 pins single-flight refresh.
3. **A recovery code must sign in exactly once,** even when two requests race. A recovery session must not be able to do anything except add a passkey or manage codes. Task 3 pins both.
4. **A stranger asking for a private snapshot's key must get exactly what an unknown key gets** (404, `no-store`), including with a forged `If-None-Match`. Task 8 pins this.
5. **Logging out on a shared browser must make the next "Log in" ask for a passkey again** (RP-initiated logout). Task 7 and Task 11 pin this.

```js
// SPDX-FileCopyrightText: 2026 The TinyLap contributors
//
// SPDX-License-Identifier: MPL-2.0

// The permission matrix of the identity spec §5, as data. Every app checks
// workspace access with can(); nothing compares role names by hand.

/** @typedef {'owner' | 'admin' | 'member'} Role */
export const ROLES = /** @type {const} */ (['owner', 'admin', 'member']);

const MATRIX = {
  'track.read': ['owner', 'admin', 'member'],
  'track.save': ['owner', 'admin', 'member'],
  'track.share': ['owner', 'admin', 'member'],
  'track.copy': ['owner', 'admin', 'member'],
  'track.delete': ['owner', 'admin'],
  'invite.manage': ['owner', 'admin'],
  'member.remove': ['owner', 'admin'],
  'admin.manage': ['owner'],
  'owner.transfer': ['owner'],
  'club.manage': ['owner'],
  'club.leave': ['admin', 'member'],
};

export const ACTIONS = Object.freeze(Object.keys(MATRIX));

/** @param {{ workspaces?: { id: string, role: string }[] }} claims @param {string} workspaceId @param {string} action */
export function can(claims, workspaceId, action) {
  const allowed = Object.hasOwn(MATRIX, action) ? MATRIX[action] : [];
  const membership = (claims.workspaces ?? []).find((w) => w.id === workspaceId);
  return Boolean(membership && allowed.includes(membership.role));
}
```

`verify.js`:

```js
// SPDX-FileCopyrightText: 2026 The TinyLap contributors
//
// SPDX-License-Identifier: MPL-2.0

// Checks an access token the way any OAuth resource server would: the
// issuer's published keys, RS256 only, the expected issuer and audience.
// Nothing here knows which provider issued it.
import { createRemoteJWKSet, jwtVerify } from 'jose';

export class AuthError extends Error {
  /** @param {string} code @param {string} message */
  constructor(code, message, options) {
    super(message, options);
    this.code = code;
  }
}

/** @type {Map<string, ReturnType<typeof createRemoteJWKSet>>} */
const remote = new Map();

/** @param {string} issuer */
function remoteJwks(issuer) {
  let set = remote.get(issuer);
  if (!set) remote.set(issuer, (set = createRemoteJWKSet(new URL(`${issuer.replace(/\/$/, '')}/jwks`))));
  return set;
}

/**
 * @param {string} token
 * @param {{ issuer: string, audience: string, jwks?: import('jose').JWTVerifyGetKey, clockTolerance?: number }} options
 * @returns {Promise<import('./types.js').AccessClaims>}
 */
export async function verifyAccessToken(token, { issuer, audience, jwks, clockTolerance = 5 }) {
  try {
    const { payload } = await jwtVerify(token, jwks ?? remoteJwks(issuer), {
      issuer, audience, algorithms: ['RS256'], clockTolerance,
    });
    const workspaces = Array.isArray(payload.workspaces) ? payload.workspaces : [];
    return /** @type {any} */ ({ ...payload, workspaces });
  } catch (cause) {
    throw new AuthError('invalid_token', 'The access token is not valid.', { cause });
  }
}
```

### Task 6: `packages/auth` — the backend-for-frontend

**Files:**
- Create: `packages/auth/{crypto.js,bff.js}`, `packages/auth/test/{crypto,bff}.test.js`, `tools/test-env.js`
- Modify: `packages/auth/index.js`, `packages/auth/types.d.ts`, `packages/auth/README.md`

**Interfaces (produces):**
- `crypto.js`: `seal(keys: { id: string, key: Buffer }[], plaintext: string) → string` (`<kid>.<iv>.<ciphertext+tag>`, base64url, AES-256-GCM with the first key) and `open(keys, sealed) → string` (any listed key by id; throws for an unknown kid or a tampered ciphertext). Keys come from env `TINYLAP_TOKEN_KEYS="<id>:<base64 32 bytes>,<id>:<…>"`, parsed by `parseKeys(text)`.
- `createBff(options)` with `options = { issuer, clientId, clientSecret, redirectUri, postLogoutRedirectUri, resource, store, keys, scope = 'openid profile offline_access', cookieName = '__Host-tinylap-session', secureCookies = true, fetchTimeoutMs = 15000 }`. `store` implements:

```js
/**
 * @typedef {object} SessionStore
 * @property {(id: string) => Promise<StoredSession | null>} get   // id is the SHA-256 of the cookie value
 * @property {(id: string, session: StoredSession) => Promise<void>} set
 * @property {(id: string) => Promise<void>} delete
 * @property {(userId: string) => Promise<void>} deleteUser
 * @typedef {{ userId: string, sealedTokens: string, createdAt: number, expiresAt: number }} StoredSession
 */
```

  It returns:
  - `login(req) → { status: 302, headers }`, with `returnTo` validated as a same-origin relative path starting with a single `/`;
  - `callback(req) → { status: 302, headers }`, sets the session cookie;
  - `logout(req) → { status: 302, headers }`, revokes the refresh token, then RP-initiated logout;
  - `session(req) → Promise<{ userId, accessToken, claims } | null>`, which refreshes when the access token has under 60 s left, with **at most one refresh in flight per session id**;
  - `requireSameOrigin(req) → boolean`: `Sec-Fetch-Site: same-origin`, else `Origin` equal to the app origin.

  Pending-login state (`state`, `nonce`, PKCE verifier, `returnTo`) lives in a short-lived sealed cookie `__Host-tinylap-login` (10 minutes, `SameSite=Lax`).

  Errors: `invalid_grant` on refresh deletes the session and returns null. Network errors, 5xx and timeouts throw `AuthError('unavailable')`, which apps map to 503.
- `tools/test-env.js`: `startSuite()` starts `accounts` (via `startAccounts`) and returns `{ issuer, clientId, clientSecret, plannerOrigin(port), signInUser(jar) }`. `signInUser` creates a user and a session cookie for use without a browser, through the test-only session helper from Task 2.
